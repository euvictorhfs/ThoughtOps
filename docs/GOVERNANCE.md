# Governance

## Decision classes

- Editorial: clarity without semantic change.
- Compatible: adds an optional contract or template.
- Behavioral: changes default system behavior.
- Constitutional: changes an invariant.
- Personal: changes Workspace identity, preference, memory or objective.

Behavioral and constitutional changes require an ADR. Personal changes require user approval and Workspace history.

## ADR lifecycle

Proposed → accepted or rejected → superseded when replaced.

An ADR states context, decision, alternatives, consequences, privacy/autonomy impact, compatibility and migration.

## Versioning

- Patch: clarification or compatible correction.
- Minor: new optional capability or contract.
- Major: incompatible meaning or required migration.

Foundation v1 may evolve without claiming semantic version tags until the first release tag is intentionally created.

## Review cadence

A quarterly system review is recommended. Review evidence, unused rules, contradictions, privacy, role effectiveness and future requests. No review is automatic in Foundation v1.

## Core promotion

Workspace learning reaches Core only through a separate, anonymized proposal. Silence is not consent.

## Future capability rule

Dashboards, integrations, retrieval and automation remain roadmap items until explicitly requested, designed, permissioned and validated.
